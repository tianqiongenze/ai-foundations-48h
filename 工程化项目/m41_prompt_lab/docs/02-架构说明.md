# 02 架构说明（TOGAF 四域视角）

> 项目：LLM 故障诊断·三版 Prompt

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 把'Prompt 感觉'变成可测量指标 |
| 数据架构 | 问题（只给症状）+ 三种 system prompt → 质量分 |
| 应用架构 | core 通道抽象 + 三版 Prompt + 评分；pipeline 对比输出 |
| 技术架构 | Python 3.12 + conda ai48；零依赖（可选连 mock LLM）；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 通道抽象 + 三版 Prompt + 评分 | `MockChannel()/call()/score()/compare()` |

## 依赖方向
```
run.py  →  pipeline  →  core（纯函数，零依赖）
               ↓           ↑
            io_utils ←── report
               ↑
            config（YAML 驱动）
```
**规则**：下层不得反向依赖上层；`core` 不 import `io_utils`（保持可单测）。

## 关键质量属性
- **可测试性**：core 为纯函数 → 单测无需 mock 文件系统
- **可配置性**：阈值全部外置 YAML
- **可复现性**：种子固定于配置
