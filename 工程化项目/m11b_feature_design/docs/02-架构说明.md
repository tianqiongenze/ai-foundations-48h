# 02 架构说明（TOGAF 四域视角）

> 项目：特征设计与优化

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 把'凭经验挑特征'变成可量化验证 |
| 数据架构 | 振动窗口 → 5 维特征 → 标签 → 重要性排序 |
| 应用架构 | core 提纯函数特征 + RF 排序；pipeline 输出 Top-N |
| 技术架构 | Python 3.12 + conda ai48；numpy/sklearn；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 时域/频域特征 + 重要性 | `feats_time()/feats_freq()/rank()` |

## 依赖方向
```
run.py  →  pipeline  →  core（纯函数，零依赖）
               ↓           ↑
            io_utils ←── report
               ↑
            config（YAML 驱动）
```
**规则**：下层不得反向依赖上层；`core` 不 import `io_utils`（保持可单测）。

## 关键质量属性
- **可测试性**：core 为纯函数 → 单测无需 mock 文件系统
- **可配置性**：阈值全部外置 YAML
- **可复现性**：种子固定于配置
