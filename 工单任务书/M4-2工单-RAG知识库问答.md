### 知识四要素详解（V1.2深度版·与授课PPT同源）

**B01 RAG三步**
- 定义：知识切分→向量检索→引用生成——开卷考试三步抄法
- 使用场景：让LLM答企业内部资料——不靠死记硬背
- 应用实例：检索top3条目→拼进prompt→生成带引用答案
- 扩展与误区：误区：全资料塞prompt——token贵且答非所问
- 原理：RAG三步=切分(知识库切块)→检索(问题找相关块)→生成(相关块+问题喂LLM)——让模型'开卷考试'，答案有出处
- 判断依据：知识库问答（值班助手）必用RAG：纯LLM靠记忆必幻觉，RAG给它资料再答——有据可查的生成
- 逐行解释：chunks=split(docs,500字); emb=embed(chunks) 向量化入库；hits=search(embed(q),top_k=3) 检索最相关3块；answer=llm(q+hits) 带着资料答——三步流水线
- 进阶优化：重排序rerank提升检索精度；查询改写（口语转检索语言）；进阶GraphRAG知识图谱关联——检索质量决定RAG上限

**B02 切分粒度**
- 定义：太碎丢上下文、太整检索糊——先按条目切
- 使用场景：维修手册按故障条目切——每条自成一体
- 应用实例：chunk_size=500, overlap=50 起步再调
- 扩展与误区：粒度没有万能值——用检索准确率反推调整
- 原理：切分粒度=块太大检索稀释（一块塞三主题）、太小上下文碎（答案缺前因）——500字+10%重叠是文档类常用起点
- 判断依据：运维手册/故障案例按'语义单元'切：小节标题处切，别在表格中间拦腰斩——粒度随文档结构调
- 逐行解释：chunk_size=500, overlap=50 相邻块重叠防'关键句恰在边界'被切碎——切完抽样人审5块看完整度
- 进阶优化：递归切分（先按标题再按段落）；表格整块不切；chunk元数据（设备型号/章节）带进检索过滤——精检

**B03 检索双解**
- 定义：重合度打分直观→Chroma向量库工程实现——两解递进
- 使用场景：教学先用关键词打分理解检索原理
- 应用实例：collection.query(embeddings, n_results=3)
- 扩展与误区：误区：检索=模糊匹配——语义检索靠向量相似度
- 原理：检索双解=关键词(BM25精确匹配'3号泵')与向量(语义相近'异响≈异常声音')——生产上混合检索(hybrid)两路并取
- 判断依据：型号/编码类查询关键词准、描述类查询向量准——先判断查询类型再选路，或两路都跑融合排序
- 逐行解释：bm25_hits=search_bm25(q); vec_hits=search_vec(q,top_k=5); fused=rrf(bm25,vec) 倒数排名融合——两路优势互补
- 进阶优化：RRF融合公式简单稳健；进阶cross-encoder重排；检索评测（recall@k）用标注问题集量化——别拍脑袋换方案

**B04 引用标注**
- 定义：每条建议挂条目ID——可点开溯源
- 使用场景：质检员要核实AI说的对不对——溯源即信任
- 应用实例：answer += ' [依据: 手册§3.2]'
- 扩展与误区：无引用的AI建议=口头承诺——产线只认可溯源
- 原理：引用标注=答案每条建议后挂[出处:文档名#块]：LLM只被允许用检索到的资料回答——用户可点开验证，可信度立起来
- 判断依据：值班助手要'每句话有出处'：输出格式约定{answer, refs[]}——没出处的回答标记'无依据，仅参考'
- 逐行解释：prompt约束'仅根据以下资料回答并标注来源[1][2]'；资料编号与引用映射表随答案返回——前端渲染成可点引用
- 进阶优化：引用率指标（带出处的答案占比）；无资料命中时走'转人工'而非硬编——诚实降级

**B05 幻觉治理**
- 定义：检索为空时宁说'查无依据'不硬编——底线意识
- 使用场景：手册里没有的故障必须坦白不知道
- 应用实例：if not hits: return '未在资料中找到依据'
- 扩展与误区：幻觉是RAG头号风险——'我不知道'是好答案
- 原理：幻觉治理=三管齐下：检索兜底(先查再说)、置信度门槛(分低转人工)、事后校验(关键数字回查源)——不指望模型自觉
- 判断依据：对'数字/型号/操作步骤'这类错不得的内容：生成后用规则校验（该型号存在吗？步骤序号连续吗？）——机器审机器
- 逐行解释：if retrieval_score<threshold: return '资料不足,转人工' 低分拒答；extract(answer里的型号)∈知识库型号集 校验通过才放行——两道闸
- 进阶优化：幻觉率指标进监控（抽检标注）；用户反馈'点踩'回流标注；prompt端'不确定就说不知道'降低编造倾向——组合拳

**B06 评测分口径**
- 定义：检索准确率与生成质量分开评——两头各管各
- 使用场景：答错时先定位：检索没找到还是生成编造
- 应用实例：检索命中率单独统计，再评答案质量
- 扩展与误区：混评找不到病灶——分开测才能对症下药
- 原理：评测分口径=检索分(召回率：该找到的找到了吗)与生成分(忠实度：答案忠于资料吗)分开评——两段各自可优化
- 判断依据：RAG优化先评检索再评生成：检索不行改切分/换embedding；生成不行改prompt——分而治之，别混着一锅调
- 逐行解释：recall@5=命中块在top5的比例（人工标注50问）；faithful=答案是否仅含资料内容（LLM当裁判+抽检）——两张记分牌
- 进阶优化：建立黄金问题集（50题标准答案）版本化；每次改动跑回归——评测驱动开发的RAG版
